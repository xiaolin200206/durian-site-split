## 1. 单元嵌套于折的方差分解（`scripts/analyse/nested_decomposition.py`）

原来的交叉分解在 GWHD / BreaKHis / HAR 上作用于「折的聚合分数」，所以分不清
两件事：训练集里少了哪组单元，和组里被打分的是哪个单元。拟合
`y = μ + M + F + U:F + S + ε` 到 per-unit 分数上，两者分开：

| | 折（训练集） | **单元（折内）** | 模型 | 种子 | 残差 |
|---|---|---|---|---|---|
| GWHD | 4.0% | **62.9%** | 0.6% | 2.9% | 29.6% |
| BreaKHis | 0.0% | **86.8%** | 0.0% | 0.0% | 13.2% |
| HAR | 1.9% | **81.8%** | 5.1% | 0.0% | 11.3% |

三个结论，都写进了 Supp Table 14：

- **单元分量比折层面的分析显示的更大。** BreaKHis 从 78.7% 升到 86.8%，
  HAR 从 56.1% 升到 81.8% 且模型份额从 14.6% 降到 5.1%。先对折内单元
  求平均再分解，把一部分效应藏进了折项里。
- **「训练集里少了哪组单元」几乎不贡献**，0–4% 且区间都含零。在 37–38 个
  训练 session、64–66 个训练病人、24 个训练受试者的规模上，换一组留出
  单元不会可测地改变模型。这与 dose-response 曲线早早变平一致。
- **GWHD 的种子反例只存在于折聚合层面。** 交叉分解里种子占 61.2%，这里
  种子主效应只有 2.9%，那部分变异转入残差（含 seed × unit 交互）：种子
  不是把整折抬高或压低，而是改变它在哪些 session 上表现好。两句话说的是
  同一批 run，回答的是不同问题，正文两处都保留了。

每折单元数不平衡比 1.00–1.13，矩估计够用；更不平衡的设计要改 REML。

## 2. 最小单元阈值扫描（`scripts/analyse/unit_threshold_sweep.py`）

把阈值从 5 提到 50，单元间 s.d. 基本不动：GWHD 保留 97%、BreaKHis 102%、
HAR 100%，durian 提到 20 张时保留 95%。所以「单元间跨度大」不是小单元的
度量噪声。durian 提到 20 只剩 8 个 burst，那一列是界定而非证实，与
Supp Table 3 的 burst 阈值敏感性互为对照。写进 Supp Table 15。

原计划的「单元内 item bootstrap」做不了：已发布的 per-unit 表记的是分数
和 item 数，没有逐 item 结果。Methods 里直接说明了这一点，用阈值扫描代替。

## 3. BreaKHis 的类别对照（同一脚本）

patient fold 按 item 数装箱、未做类别平衡，所以病人身份与类别构成混在一起。
在各标签内部重做：良性 24 人单元分量 69.5%，恶性 57 人 82.4%，都仍占主导。
与 durian 的单类对照同理，写进 Supp Table 15。

顺带一个可写进正文的观察：良性子集又难又散（24 人，均值 0.820，s.d. 0.230），
恶性 57 人是 0.940 / 0.128，全库最差的病人是良性。pooled 0.906 是两个相差
十二个点的群体的平均。

## 1. "selection-free estimate" 说过头了（已改措辞）

早停 patience=50 意味着「最后一轮是第几轮」本身由留出单元的分数决定，除非
该 run 跑满 150 轮上限。所以 last-epoch 权重去掉的是 **best-epoch 选择**，
不是全部选择。原稿写 "which no validation signal selected / selection-free
estimate" 站不住。

已改：正文、Methods、Fig 5 图注、Supp Table 6 全部改成「isolates best-epoch
selection，图中数字是总选择效应的下界」，并在 Supp T6 加了一段说明真正
untouched 的协议长什么样。两个 arm 都带着同样的残余早停选择，所以**两者之差**
才是这些行支持的量——这一点也写进去了。

**待办（不用 GPU，但要开机读文件）**：数一下每个 run 的 `results.csv` 行数，
统计有多少 run 跑满了 150 轮。跑满的那些早停从未触发，最后一轮由预算决定，
对它们而言 last-epoch 就是真正无选择的。如果比例很高，这条质疑基本消解；
如果很低，就照现在的下界写法。

## 2. durian 的两种 regime 训练集大小不同（已改，且方向有利）

原 Methods 写 "the split rule is the only difference between them"，在 durian
上是错的：

| | 训练 | 验证 |
|---|---|---|
| item-level 80/20 | 662 | 165 |
| leave-one-farm-out | **680–770** | 57–147 |

unit-level 训练数据反而多 3–16%，分数还是掉 37–44%，所以训练量解释不了这个
下降，方向上使报告值偏保守。另外三个数据集两种 regime 都是五折、训练集大小
按构造相同（HAR 两边平均都是 8,239 windows），这是干净的对照。

已改：Methods 的 Partitions 段落、Results 的第一段、Supp Table 2 新增一段
说明。审读建议的 training-count-matched 重跑因此不必做——同一个质疑用现有
数据就能封死，而且封得更彻底（不是"匹配后仍然掉"，而是"劣势方反而是被比较
的那一边"）。

## 3. 采纳的一条表述升级

审读指出 pooled 分数是 instance-weighted、per-unit 是 unit-weighted，两者是
**不同的 estimand**：随机取一张图的期望表现，和随机取一个农场/病人/受试者的
期望表现，不是一回事，而部署问的通常是后者。这个说法比原来的"多报一个 SD"
高一档，已写进 Discussion，并把报告建议从三条扩成四条（训练单元数、评价
单元数、离散度、**加权口径**）。两种口径的差值在 Supp Table 9 里已经有了：
GWHD +0.056、durian −0.037、BreaKHis +0.004、HAR +0.001。

**unitcheck 作为 linter。** 采纳它的包装建议，在 Discussion 里把定位从"事后
审计工具"改成"建 benchmark 的流水线里可以当 linter 跑"。

## 它说过头的一条

**模型同质化。** 它认为 0.4% 的模型分量是"人为压低"的假象。这只对了一半：
BreaKHis 和 GWHD 确实只有同族容量档次，但 durian 是 RT-DETR（transformer）
对 YOLO（CNN），模型分量 1.1%；HAR 是感知机对随机森林，只共享输入特征，
嵌套分解下模型分量 5.1%。**四个数据集里已有两个跨了架构族，都是低分量。**
所以"跨族后单元仍主导"已有两条独立证据。

## 唯一值得花钱的建议

**BreaKHis 补一个 ResNet-50 或 ConvNeXt。** 它建议 GWHD 也补 Faster R-CNN，
我不同意——GWHD 补一个跨族检测器要重训 30 个检测 run，是 BreaKHis 的数倍

五折五种子 50 个 run。

做完之后能说的话是：在一个模型分量最低的数据集上换成真正不同的架构族，
单元分量仍然主导。这会把 Gemini 那条质疑从"有道理"变成"已排除"。

不做也能投，因为跨族证据已有两条。这是加分项，不是 blocker。

# 补记六：早停质疑已量化（epochs.csv）

第三、四位审读都指出 last-epoch 不是 selection-free，因为 patience=50 意味着
「最后一轮是第几轮」仍由留出单元决定。这条对，但**可以量化**：跑满 150 轮
上限的 run 早停从未触发，对它们而言最后一轮由预算决定，没有任何选择。

从 135 个 durian 训练日志读出轮数（`results_durian/run_epochs.csv`）：
109 个早停触发，26 个跑满。

| 子集 | n | selected | final | 差 |
|---|---|---|---|---|
| unit-level 跑满 | 14 | 0.2844 | 0.2332 | **+0.0513** |
| unit-level 早停 | 106 | 0.2949 | 0.2158 | +0.0792 |
| item-level 跑满 | 12 | 0.4851 | 0.4779 | **+0.0071** |
| item-level 早停 | 3 | 0.5237 | 0.5133 | +0.0104 |

**在只剩 best-epoch 选择的子集上，七倍的不对称依然成立。** 所以这个效应不是
早停造成的假象。正文加了一句，Supp Table 6 加了完整的表和两条限制。

## 意外收获：早停率本身就是机制的证据

item-level 的 15 个 run 里 12 个跑满（80%），unit-level 的 120 个里只有 14 个
（12%）。item-level 验证集在训练集里近似重复，所以分数一直在改善、耐心计数器
从不耗尽；unit-level 是真正的留出目标，50 轮内就停滞。

**同一个性质既让 best-epoch 选择在 item-level 几乎无害，也让早停在那里几乎
从不触发。** 这不是设计出来的对照，是数据自己给的，已写进 Supp Table 6。

## 两条必须自己说的限制

- 跑满的 run 不是随机子集：它们恰恰是从未连续 50 轮不改善的那些，所以两个
  子集在停止规则之外还有别的差异，+0.051 不是全样本效应的无偏估计。
- 按模型拆开两个子集排序不一致（RT-DETR-L +0.030 对 +0.100，YOLO11m +0.079
  对 +0.061，YOLO11n +0.045 对 +0.075），n = 3、4、7 太小。
